# 서비스 중심 MVP 구현 기준

2026-09-08 RAG 리팩토링 기준. **해상무역 서류와 금융일정을 연결해 놓치기 쉬운 일정상 위험을 찾고, 필요한 금융정보를 검색해 담당자의 검토를 돕는다.** 실제 금융 판단이나 상품 가입을 대신하지 않는다.

> 버전 안내: `docs/TradeFlow-MVP-Guide.pdf`는 정해진 본문을 조회하고 원문만 발췌하던 **이전 버전 설명서**다. 현재 구조는 이 문서와 `docs/rag-corpus-guide.md`, README를 기준으로 확인한다. 이번 리팩토링에서 이전 PDF를 재생성하지 않았다.

## 세 충돌에 대한 서비스 계약

| 충돌 코드 | 서비스 코드 | 검색해서 설명할 정보 | 추가 확인 |
| --- | --- | --- | --- |
| WORKING_CAPITAL_LOAN_MATURITY | LOAN_REPAYMENT_REVIEW | 미상환 시 불이익·연장 심사 조건·유지 및 갱신 서류 | 잔액·다른 입금·현재 계약은행 상담 |
| FX_FORWARD_MATURITY | FX_SETTLEMENT_REVIEW | 기존 매도 계약의 결제 의무·중도해지 동의·정산 손실 위험 | 계약 통화·금액·확보한 외화·은행의 변경 및 정산 조건 |
| SUPPLIER_PAYMENT | SUPPLIER_FUNDING_REVIEW | 추가 운영자금이 필요할 때의 용도·비용·증빙, 수출채권 보유 입력 시 매입 조건·서류·비용·환매 의무 | 실제 추가 필요액·지급 목적·거래 증빙 |

서비스별 자연어 검색 질문과 고객 확인 체크리스트는 `app/services/service_policy.py`가 정한다. LLM은 검색된 근거에 기반해 쉬운 설명을 작성한다. 서비스 카드의 INFORMATION은 검토할 정보가 있다는 뜻이지 금융상품 이용 가능 판정이 아니다. REVIEW_REQUIRED는 확인 필요, NO_CONFLICT는 해당 일정의 선후관계상 충돌 없음을 뜻한다.

공급자 지급일이 먼저라고 실제 자금 부족을 단정하지 않는다. 보유 잔액·다른 입금·환율을 반영한 부족액 계산과 고객의 답변을 받아 후속 판단하는 대화 기능은 아직 없다.

## 전체 구조와 역할

| 구성 | 책임 |
| --- | --- |
| Supervisor | 요청에 필요한 단계와 순서를 계획하고 허용된 도구를 호출한다. 별도 Planner는 없다. |
| Document Agent | PDF 텍스트 또는 OCR에서 날짜·금액·통화·문서번호와 근거를 추출한다. |
| Finance Advisor Agent | 엑셀 거래 연결·예상 입금일·규칙 기반 충돌 계산 도구를 사용하고, RAG 검색 후 질문별 근거 선택과 단일 본문 설명을 수행한다. |
| Report Generator | 구조화된 결과를 PDF에 배치한다. 새로운 금융 판단을 만들지 않는 Python 도구다. |

## 실행 흐름

1. PDF와 금융일정 엑셀, 거래 ID를 입력한다.
2. Supervisor가 단계를 계획하고 Document Agent가 핵심 값을 제출한다. 코드가 원문·페이지와 대조한다.
3. 금융 도구가 엑셀에서 해당 거래와 문서번호를 연결한다. 지원되는 결제조건과 기준일이 확인될 때 예상 대금 유입일을 계산한다.
4. Python 날짜 규칙으로 대출 만기·선물환 결제·공급자 지급을 비교한다. 같은 날이나 필수 입력 미확인은 판단을 보류한다.
5. 확인된 충돌에 서비스 정책의 자연어 질문을 연결한다. 대출 3개, 선물환 2개, 공급자 지급 기본 2개이며 수출채권 보유 입력 시 조건·서류·비용·환매 의무에 관한 4개를 추가한다.
6. 거래 종류에 맞는 검토 완료 자료군에서 ChromaDB 의미 검색을 수행한다. **정답 페이지·본문 주제는 필터링하지 않는다.** 질문마다 여러 후보 청크에서 관련 본문 상위 3개를 검색한다.
7. Finance Advisor의 `choose_financial_evidence`에는 한 충돌의 핵심 질문 2-3개와 검색 후보를 전달한다. 질문마다 직접 답을 뒷받침하는 **근거 ID 또는 `null`만 선택**하고 설명은 작성하지 않는다. 각 질문에는 해당 검색 질의가 실제로 찾은 본문 ID만 허용한다.
8. 근거가 선택된 질문마다 `explain_financial_evidence`를 따로 호출한다. 입력은 **질문 하나와 선택된 본문 하나뿐**이며, 거래 상황·다른 후보·근거 ID·기존 초안은 넣지 않는다. 검색 청크를 다시 작은 문장으로 자르지 않고 전체를 읽어, 220자 이내 한 문장의 설명 또는 `null`을 반환한다. 선택·설명 실패 시 해당 설명을 보류한다.
9. 서버가 선택된 ID에서 거래·은행·자료·청크 전체 인용·페이지를 붙인다. 설명 모델이 은행이나 인용문을 직접 조합하거나 근거를 바꾸지 않는다. 허용 ID·파일·페이지·해시를 확인하고 색인된 본문을 연결하며, 생성 설명과 고정 체크리스트를 구분한다. 자유 금융 설명을 별도의 경고 문구로 내보내지 않는다.
10. 상황·핵심 설명·근거 페이지·추가 질문·제한을 서비스 카드와 보고서에 담는다. 검색문·후보 수·선택한 본문도 검증 기록에 남긴다.

## 왜 이전 방식과 다른가요?

| 항목 | 이전 고정 본문 방식 | 현재 검색·설명 방식 |
| --- | --- | --- |
| 색인 | 사람이 정답 문장의 시작·끝 문구를 지정 | 검토한 페이지 범위의 여러 문단·절을 분할 |
| 검색 범위 | 충돌 + 특정 자료 + 특정 주제 | 충돌·거래 조건에 맞는 자료군 |
| 검색 역할 | 조건별 후보가 하나여서 사실상 고정 조회 | 여러 후보 중 질문과 관련된 본문을 선택 |
| AI 역할 | 핵심 원문 한 문장 선택 | 원문 근거에 기반한 쉬운 설명 생성 |
| 출처 | 선택한 발췌문의 페이지 | 생성된 설명마다 인용문·페이지 연결 |

검색어를 매번 AI가 새로 만들어야 RAG가 되는 것은 아니다. **동일한 자료군 안에서도 질문이 달라지면 필요한 본문을 찾아내는지**가 중요하다. 설명 생성에는 환각 위험이 있으므로 검색 결과만 사용하고 출처를 붙이되, 원문 일치 검사만으로 설명의 의미까지 자동 입증했다고 주장하지 않는다.

근거 ID는 **검색 후 선택된 본문 청크에 붙이는 식별자**다. 색인 전에 정답 문장이나 페이지를 정해 두는 방식이 아니다. 설명에는 선택한 청크가 뒷받침하는 내용만 담고, 상위 조건·시점·예외를 유지하도록 지시한다. 질문별 허용 근거도 정답 파일이 아니라 **그 질문의 실제 검색 결과**에서 정한다. 이 지시와 ID 검사는 의미적 정확성을 보장하는 자동 검증과 다르다.

근거 선택과 단일 본문 설명은 Finance Advisor 내부의 고정 Workflow이며 새로운 자율 Agent나 초안 재검토 루프가 아니다. `gpt-5-nano` Flex를 유지하고 두 단계 모두 `reasoning_effort=high`를 적용한다. 전체 예시 실행은 최대 20회, RAG 단독 검증은 최대 13회로 유료 호출을 제한하며 호출당 출력 상한은 추론을 포함해 6,000토큰이다. 다른 후보의 내용을 선택된 출처에 잘못 붙이는 문제를 줄이려는 설계이지 금융전문가 검증이나 자동 의미 정확성 보증은 아니다.

## 보고서의 핵심 질문

검색은 11개 정보 요구를 다루지만 고객에게 모든 검색 결과를 길게 나열하지 않는다. `get_answer_slots()`가 충돌별로 구분되는 질문을 2-3개 정해 동일한 위험 설명만 반복되거나 핵심 조건이 빠지는 문제를 줄인다. 각 질문에는 관련 근거로 답하거나 확인 불가(`null`)로 응답해야 한다. 질문을 미리 정하는 것이지 답이나 정답 페이지를 정하는 것은 아니다.

| 충돌 | 답변할 핵심 질문 |
| --- | --- |
| 대출 만기 | 원금 미상환 시 불이익 / 연장 거절 조건 / 유지·갱신 준비자료 |
| 선물환 결제 | 만기 결제 의무 / 중도해지 동의·확인사항 |
| 공급자 지급, 수출채권 보유 입력 있음 | 운영자금의 사용 제한 / 수출채권 매입 조건이나 서류 / 환매 의무 |
| 공급자 지급, 수출채권 보유 입력 없음 | 운영자금의 사용 제한 / 운영자금 상환 관련 비용 |

공개 결과의 각 설명에는 `slot_id`, `question`, 답변, 근거 인용과 페이지가 연결된다. 근거 부족·입력 확인·서비스 범위에 관한 주의 문구는 서버가 작성하며, LLM이 인용 없는 금융 주장을 `warnings`로 추가하는 경로는 두지 않는다. 모든 비용·서류·위험을 빠짐없이 설명하는 종합 금융상담 기능은 아니다.

## 자료 구성과 검색 예시

활성 자료는 공식 PDF 3개, 검토한 24페이지다. 정확한 원문·범위·11개 질의는 `docs/rag-corpus-guide.md`에 정리했다.

- 신한은행 기업대출 상품설명서: 고객용 12-21페이지 전체.
- HSBC 수출채권할인 기본 계약: 계약 본문 2-9페이지 전체.
- 중국은행 선물환 고객매도 설명서: 설명 본문 1-6페이지 전체.

HSBC 공통 무역금융 설명서는 서로 다른 상품의 비용이 함께 있어 이번 검색에서는 비활성화했다. 수출채권할인 비용은 해당 계약의 할인수수료·조정수수료에서 찾는다.

예를 들어 대출 만기가 예상 입금일보다 먼저 돌아오면 다음과 같이 서로 다른 정보 요구를 검색한다.

- “기업대출 만기에 원금을 상환하지 못할 때 연체이자와 불이익은 무엇인가?”
- “기업대출 계약기간을 연장할 때 적용되는 조건은 무엇인가?”
- “기업대출 유지·갱신을 위해 은행에 제출해야 하는 재무제표와 매출 관련 서류는 무엇인가?”

세 질문 모두 같은 기업대출 자료군을 검색하지만 반환할 본문·페이지를 미리 지정하지 않는다. 검색된 내용에 따라 미상환 시 유의사항, 연장 조건, 준비자료를 설명하며, 해당 은행 자료가 고객의 실제 계약에 그대로 적용된다고 단정하지 않는다.

## 중단·보류 규칙

- 충돌 없음: RAG 생략.
- 날짜·거래 연결·통화·매도 방향 미확인: 먼저 입력 확인 요청.
- 수출채권 미확인: 채권 관련 질의와 PDF 제외.
- 미검토·비활성 자료: 검색 제외.
- 파일·카탈로그가 색인과 다름: 재검토·재색인 요청.
- 원문 인용이 없거나 출처 검증 실패: 해당 설명 제외·보류.
- 근거 선택·단일 본문 설명 호출 실패 또는 답변 형식 오류: 해당 설명 보류.
- 생성 설명에 ‘아래·다음·위 각호’처럼 빠진 목록을 가리키는 표현이 남음: 해당 질문만 보류. 원문·조항 번호 자체는 차단하지 않으며, 이 읽기 검사가 의미 정확성을 보증하지는 않음.
- 질문에 답할 근거가 부족함: 확인할 수 없다고 표시. 다른 상품 조건이나 일반 지식으로 채우지 않음.

## 검증과 공개 범위

모의 LLM 단위 테스트와 실제 API 실행은 구분한다. 실제 검색 후보 수·질문별 반환 청크·생성 설명을 함께 확인하며, 시험에서 정해 둔 페이지를 검색 필터에 넣지 않는다. 테스트 통과는 금융 전문가의 검토나 상품 적합성 판정을 대신하지 않는다.

원본 PDF·은행 본문·ChromaDB·실행 로그·이를 포함한 보고서는 공개 저장소에 넣지 않는다. 특히 중국은행 PDF는 인용·제3자 배포에 사전 동의를 요구하므로 공개 서비스나 결과물에는 동의 확보 또는 사용 조건이 확인된 대체 자료가 필요하다. 금융자료는 상담 참고정보이며, 실제 대출 승인·계약 변경·송금은 하지 않는다.
