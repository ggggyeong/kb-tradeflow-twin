# RAG 자료 선정·검색 기준

2026-09-08 리팩토링 기준. **충돌에 필요한 정보를 여러 본문에서 검색하고, 검색한 근거로 설명한다.** 특정 주제에 정답 본문 하나를 연결하던 기존 방식을 대체한다.

> 버전 안내: `docs/TradeFlow-MVP-Guide.pdf`는 고정 본문 조회·원문 발췌 방식의 이전 버전이다. 현재 자료·질의·설명 생성 방식은 이 문서와 `docs/service-mvp.md`를 기준으로 확인한다. 기존 PDF는 이번 변경에서 재생성하지 않았다.

### 기존 HSBC 공통 비용 설명서를 비활성화한 이유

`hsbc_trade_finance.pdf`는 원본·출처 기록을 보존하지만 이번 검색에서는 `ARCHIVED`, `enabled=false`로 제외했다.

이 공통 설명서의 1페이지에는 수출환어음 매입의 **환가료**와 매출채권 할인, 수입금융·지급보증 등 다른 거래의 비용이 함께 나온다. 수출채권 보유 입력만으로 수출환어음 매입 계약을 가정할 수 없다. 따라서 환가료 설명을 수출채권할인 계약의 비용으로 연결하지 않는다.

대신 활성 HSBC 계약에 있는 **할인수수료·조정수수료와 환매 관련 조항 자체를 검색**한다. 비용 항목을 설명할 수는 있지만 빈 마진·한도란을 채우거나 실제 고객 비용을 계산하지 않는다. 기존 KB 한 장짜리 자료도 이번 검색에서 활성화하지 않는다.

### 문서 품질과 적용 범위

- 신한 자료는 기업대출 공통 설명서다. 특정 운전자금 상품의 전체 가입조건·한도·신청 서류를 제공하는 문서로 표현하지 않는다. 기업대출 유지·갱신 시 요구되는 자료와 신규 신청 서류를 구분한다.
- HSBC 계약은 은행의 수락·한도·선결 요건과 고객의 환매 의무가 있는 계약이다. 채권 보유 입력만으로 매입 승인·지급일 확보·비소구를 보장하지 않는다.
- BOC p.5의 중도해지 내용은 p.6으로 이어진다. 해지 가능 여부만 보고 비용·손실·유동성 유의사항을 빠뜨리지 않는지 검색과 답변을 함께 확인한다.
- 표 안의 예시 숫자, 미기입 계약란, 설명용 환율을 고객에게 적용된 조건으로 사용하지 않는다. 네이티브 PDF도 문자 순서·표 추출 오류가 있어 실제 계약 해석을 자동 확정하지 않는다.
- 다른 은행의 조건을 하나로 합치지 않는다. 출처 은행을 표시하고, 고객의 실제 계약은행·약정을 별도로 확인하도록 한다.

## RAG에는 어떤 질문을 보내나요?

질문은 충돌별 정보 요구를 표현하는 자연어 템플릿이며, 파일명·페이지·정답 주제 ID는 넣지 않는다. 날짜와 금액은 일정 설명에 사용하고 공식 자료 검색에는 불필요하게 넣지 않는다.

| 충돌 | 실제 검색 질문 |
| --- | --- |
| 대출 만기 | 기업대출 만기에 원금을 상환하지 못할 때 연체이자와 불이익은 무엇인가? |
| 대출 만기 | 기업대출 계약기간을 연장할 때 적용되는 조건은 무엇인가? |
| 대출 만기 | 기업대출 유지·갱신을 위해 은행에 제출해야 하는 재무제표와 매출 관련 서류는 무엇인가? |
| 선물환 결제 | 선물환 고객매도 계약에서 약정환율과 계약금액을 정하고 만기에 결제하는 방식은 무엇인가? |
| 선물환 결제 | 선물환 매도 계약의 중도해지에 필요한 은행 동의와 정산금액 및 손실 위험은 무엇인가? |
| 공급자 지급 | 공급자 대금 지급을 위해 기업 운전자금을 검토할 때 자금용도 제한과 거래 대상 및 증빙 자료는 무엇인가? |
| 공급자 지급 | 기업대출 운영자금을 잠시 사용하고 상환할 때 확인해야 하는 이자와 수수료 및 중도상환 비용은 무엇인가? |
| 공급자 지급 + 수출채권 보유 입력 | 수출채권 매입 요청을 은행이 수락하는 조건과 매입 한도는 무엇인가? |
| 공급자 지급 + 수출채권 보유 입력 | 수출채권 매입의 선결 요건으로 고객이 은행에 제출해야 하는 서류와 선적서류는 무엇인가? |
| 공급자 지급 + 수출채권 보유 입력 | 수출채권 매입의 할인수수료와 조정수수료는 어떻게 정해지며 어떤 경우에 적용되는가? |
| 공급자 지급 + 수출채권 보유 입력 | 수출채권을 매입한 후 채무자가 대금을 지급하지 않으면 고객은 언제 채권을 환매해야 하는가? |

총 11개 검색 템플릿의 원본은 `app/services/service_policy.py`다. 연장 심사와 유지·갱신 서류, 수출채권의 조건·서류·비용·환매는 각각 다른 본문을 요구하므로 별도 질문으로 나눈다. `export_receivable_confirmed=true`는 사용자의 확인 입력이지, 시스템이 은행이나 채권원장을 조회해 입증한 상태가 아니다.

## 저장과 검색 방식

```text
공식 PDF
  -> 검토한 원본 해시와 페이지 범위 확인
  -> 페이지의 여러 문장·문단을 토큰 한도 내 청크로 분할
  -> 로컬 다국어 E5 임베딩 -> ChromaDB

확인된 일정 충돌
  -> 거래 종류에 맞는 자료군 선택
  -> 자연어 질문으로 여러 청크를 의미 검색
  -> 검색 근거에서 설명 생성 -> 출처·인용 근거와 함께 보고서
```

카탈로그의 활성 자료는 `index_mode="pages"`, `sections=[]`다. `include_pages`는 은행용 중복·서명란 등을 제외하는 **색인 범위**이고, 질문별 정답 페이지가 아니다. 원본 URL·개정일·검토일·해시·선정 이유·거래 구분은 계속 관리한다.

로컬 `intfloat/multilingual-e5-small`을 CPU에서 사용한다. 문서는 `passage:`, 질문은 `query:`를 붙여 384차원으로 임베딩한다. `■`·`▣`·조항 번호 등 문서 구조를 경계로 보고 제목과 뒤의 항목을 함께 유지한다. 빈 줄 뒤의 `(a)`·`(1)`·글머리표 목록은 앞의 조건 문장과 우선 묶은 뒤 길이 제한에 따라 나눠, 목록만 떨어져 검색되는 문제를 줄인다. 글자 수를 채우려고 서로 다른 절을 합치지 않으며, 정답 키워드를 지정해 본문을 고르지 않는다. 기본 최대 800자·중첩 100자와 모델 토큰 한도를 함께 고려하고, 절 경계를 넘는 중첩은 하지 않는다. 실제 임베딩 경로에서는 E5 토크나이저로 계산하여 480토큰 이내의 청크를 만든다. 페이지 정보는 인용용 메타데이터로 보존한다.

`data/knowledge/chroma_products/` 안에 `trade_finance_evidence-build-<generation>` 형식의 컬렉션을 저장한다. 현재 검색에 사용하는 실제 이름은 manifest의 `collection_name`에서 읽는다. 고객 송장·선하증권·Booking·엑셀은 거래 분석 입력이며 이 공용 금융자료 DB에 넣지 않는다.

검색 시에는 충돌 코드, 수출입 방향 및 거래 종류에 맞는 자료 ID만 제한한다. **개별 페이지나 정답 주제로 필터링하지 않는다.** 질문마다 해당 범위의 여러 청크 중 상위 3개를 검색하고, 같은 본문이 여러 질문에 나와도 근거 중복을 제거한다. 수출채권 자료는 EXPORT이며 보유 확인 입력이 있을 때에만 별도 질문으로 검색한다.

페이지별로 나누므로 페이지 경계에 걸친 조항은 여러 검색 근거를 함께 검토해야 한다. 이웃 페이지 전체를 자동으로 붙이는 기능과 금융약관 전문 해석은 지원 범위 밖이다. 질문별 후보 수·검색문·필터·선택 청크·점수를 기록해 실제로 어떤 검색이 일어났는지 확인한다.

검색 청크 **전체**를 `evidence_id`의 근거로 사용한다. 생성 직전에 문장을 다시 작게 자르면 상위 조건과 결과, 환매 의무와 사유 목록 등이 떨어질 수 있어 작은 span 분할을 사용하지 않는다. 이 ID는 검색 뒤의 출처 연결 수단이지 색인 단계에서 정답 문장을 지정하는 필터가 아니다. 근거 선택에는 한 충돌의 검색 후보만 전달하고, 설명 생성에는 질문 하나와 선택된 본문 하나만 전달한다.

`get_answer_slots()`가 충돌별 핵심 질문을 정하고, 각 질문에는 그 질문의 `query_ids`로 **실제로 검색된 청크 ID만** 허용한다. 이는 검색 단계에 정답 페이지를 지정하는 것이 아니라, 검색 후 엉뚱한 정보 요구의 근거로 답하지 않게 제한하는 방식이다.

| 충돌 | 보고서에서 답할 항목 |
| --- | --- |
| 대출 만기 | 원금 미상환 시 불이익 / 연장 거절 조건 / 유지·갱신 서류 |
| 선물환 결제 | 만기 결제 의무 / 중도해지 조건 |
| 공급자 지급 + 수출채권 보유 입력 | 운영자금 사용 제한 / 채권 매입 조건이나 서류 / 환매 의무 |
| 공급자 지급 + 수출채권 보유 입력 없음 | 운영자금 사용 제한 / 운영자금 상환 비용 |

질문별 220자 이내 한 문장, 충돌별 최대 3개 설명만 제공하므로 검색한 비용·서류 등 모든 내용을 보고서에 포함하는 것은 아니다. 서버가 선택된 근거 ID에서 은행·자료·페이지·**청크 전체 인용**을 붙이고, 공개 결과에도 `slot_id`와 질문을 보존한다.

### 근거 선택과 설명 생성을 분리

`choose_financial_evidence`는 충돌별 핵심 질문마다 실제 검색 후보 중 직접 답을 뒷받침하는 **근거 ID 또는 `null`만 선택**한다. 이 단계는 설명을 작성하지 않는다. 코드가 질문별 허용 ID인지 확인한 뒤, 근거가 선택된 질문마다 `explain_financial_evidence`를 따로 호출한다.

- 설명 호출에는 **질문 하나와 선택한 본문 하나만** 전달한다. 거래 상황·다른 검색 후보·근거 ID·기존 초안은 넣지 않는다.
- 설명 모델은 선택된 원문만 읽고 `{text: 설명 또는 null}`을 반환한다. 근거를 다시 선택하거나 다른 본문을 함께 섞어 쓰는 출력 경로는 없다.
- 답에 필요한 조건·주체·의무 발생 시점·은행의 요청이나 동의·예외를 유지하도록 지시한다. 본문으로 답할 수 없으면 `null`로 보류한다.
- 선택·설명 호출이 실패하거나 출력 형식이 맞지 않으면 영향을 받는 설명을 보류한다. 일반 지식이나 앞서 만든 초안으로 대신 채우지 않는다.

두 단계 모두 `gpt-5-nano` Flex와 `reasoning_effort=high`를 사용한다. Finance Advisor 내부의 고정 Workflow이며 새로운 Agent나 초안 재검토 단계를 추가한 것이 아니다. 전체 예시 실행의 유료 호출 상한은 20회, RAG 단독 검증은 13회이며 호출당 출력 상한은 추론을 포함해 6,000토큰이다. 무제한 재시도나 추가 금융자료 자동 수집은 수행하지 않는다.

답변에는 선택한 청크가 뒷받침하는 내용만 담고, 상위 조건·시점·예외를 유지하도록 지시한다. 코드는 허용된 ID·거래 연결·파일·페이지·해시를 확인하고, 서버가 선택된 색인 본문을 그대로 인용으로 연결한다. 고정 고객 확인 체크리스트와 생성 설명도 구분한다. LLM의 자유 `warnings` 출력은 사용하지 않으며, 인용 없는 금융 설명이 경고 경로로 노출되지 않도록 보류·범위 안내는 서버에서 처리한다.

**근거 ID·인용 원문의 일치나 설명 맥락의 분리가 금융적 타당성이나 의미적 정확성을 보장하지 않는다.** 본문 하나 안에도 서로 다른 조건이 있을 수 있으므로, 이를 섞거나 의미를 확대하는지 사람이 별도로 검토해야 한다. 자동 의미 검증을 통과했다는 보증 상태를 만들지 않는다. 근거가 없거나 조건이 불명확한 내용은 확인 불가로 남기고, 실제 적용 여부는 원문·개별 계약과 함께 사람이 검토한다.

## 어떻게 검증하나요?

- 같은 기업대출 자료군에 연체 질문과 연장 질문을 보내 서로 다른 관련 본문이 검색되는지 확인한다.
- 질문마다 후보 본문이 1개로 고정되지 않았는지, 페이지·정답 주제 필터가 없는지 검색 기록으로 확인한다.
- 수출채권 미확인, 충돌 없음, 입력 미확인에는 해당 검색을 하지 않는지 확인한다.
- 수출채권 비용 검색 결과가 활성 할인 계약의 할인·조정수수료인지 확인한다. 비활성 공통 설명서의 환가료를 섞지 않는다. 현재 짧은 보고서에서는 매입 조건·환매 의무를 우선하므로 비용 결과가 모두 설명으로 출력되는 것은 아니다.
- 실제 LLM 호출 결과에서 질문, 선택한 PDF 페이지, 설명, 인용 근거를 함께 검토한다. 테스트 통과를 금융기관 승인이나 상품 적합성 보장으로 해석하지 않는다.
- 선택·설명 호출 실패 시 해당 설명이 보류되는지 확인한다. 근거 선택·단일 본문 설명 단계 수행 여부와 사람이 확인한 최종 설명의 의미 정확성은 구분해서 기록한다.

## 재현·갱신·공개 범위

```bash
uv run python scripts/fetch_product_pdfs.py
uv run python scripts/build_product_vector_index.py --dry-run
uv run python scripts/build_product_vector_index.py
```

다운로드는 고정 공식 URL을 사용하며 기존 파일은 덮어쓰지 않는다. Agent 실행 중 임의 웹 검색이나 상품 추가는 없다. 현재 활성 원본은 모두 네이티브 텍스트 PDF이며, 이미지 PDF를 추가하면 OCR이 필요하다. 색인 자체는 유료 LLM을 호출하지 않는다.

`--dry-run`은 활성 자료·페이지·텍스트 유무를 확인한다. 실제 토큰 분할·임베딩·검색 검증을 대신하지 않는다. 원본이 바뀌면 해시만 고치지 말고 PDF 내용과 포함 범위를 다시 검토한다. manifest v7는 카탈로그·원본·모델·레코드의 일치를 검증하며, 제목·조항·목록을 반영하는 `heading-clause-list-token-budget-v3` 분할 전략을 기록한다. 예전 고정 본문 색인과 초기 페이지 분할 색인은 재생성해야 한다.

### 재색인은 새로운 컬렉션을 만든 뒤 전환

이번 로컬 반복 색인 과정에서 기존 컬렉션에 upsert/delete를 반복한 뒤, 저장된 행을 직접 읽을 수 있어도 해당 본문이 벡터 검색 상위 결과에 나오지 않는 상황을 재현했다. 동일한 본문·임베딩·질문을 새 컬렉션에 넣었을 때는 해당 결과가 검색됐다. 이는 **현재 로컬 환경에서 확인한 현상**이며, ChromaDB 전체나 모든 버전의 일반적인 결함으로 단정하지 않는다. 검색 상위 개수를 늘리거나 정답 페이지를 지정하는 방식으로 보정하지 않는다.

현재 재색인 절차는 다음과 같다.

1. 모든 청크의 임베딩을 계산한 후 새 generation 컬렉션을 생성한다. 기존 활성 컬렉션에는 덮어쓰기·삭제를 하지 않는다.
2. 새 컬렉션에 저장한 본문이 자신의 벡터로 다시 검색되는지 확인한다. 레코드 수와 청크 ID 해시도 대조한다.
3. 검증이 끝나면 임시 manifest를 원자적으로 교체해 새 `collection_name`을 활성화한다. `rebuild_strategy`는 `fresh-collection-atomic-manifest-v1`이다.
4. 이전 컬렉션은 삭제하지 않고 `previous_collection_name`으로 기록한다. 전환 전 실패하면 기존 manifest와 컬렉션을 유지한다. 보존된 이전 컬렉션은 자동 롤백 기능을 뜻하지 않으며, 여러 번 재색인하면 디스크 사용량이 늘어날 수 있다.

실행 중인 API는 Pipeline과 검색 저장소 객체를 재사용하므로 **재색인은 분석을 멈춘 상태에서 진행하고, 완료 후 API 서버를 재시작**한다. CLI도 새 프로세스로 실행하거나 Pipeline/검색 저장소를 새로 만들어 최신 manifest를 읽어야 한다. 원자적 manifest 전환이 기존 프로세스의 자동 새로고침이나 무중단 동시 운영까지 제공하는 것은 아니다. 사용하지 않는 이전 컬렉션의 자동 정리는 이번 구현 범위 밖이다.

이번 업데이트의 공개 대상은 코드·공식 링크·선정 이유·페이지 범위·합성 입력·직접 작성한 구현 설명이다. 현재 활성 RAG의 원본 PDF·모델·ChromaDB·은행 본문 및 이를 포함한 실행 로그·보고서는 추가하지 않는다. 기존 저장소에 이미 있던 KB PDF와 과거 샘플은 이번 작업에서 삭제하지 않았다. 중국은행 PDF p.6은 인용·제3자 배포에 사전 동의를 요구한다. 공개 서비스나 공개 결과물에 사용하려면 해당 동의 또는 사용 조건이 확인된 대체 자료가 필요하다. 다른 자료도 공개 다운로드를 재배포 허가로 해석하지 않는다.

이번 변경에서는 자료를 무작정 추가하거나 금융상품 종류를 늘리지 않고 기존 원본 3개의 검색 범위를 개선했다. `REVIEWED`는 개발 단계의 원문 확인 기록이며 금융기관·전문가 승인 표시가 아니다. 외부 API 검증에는 합성 거래만 사용하며, `store=False`를 공급자의 무보관 보증으로 해석하지 않는다.
