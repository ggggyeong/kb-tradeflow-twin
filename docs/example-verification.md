# 합성 예시와 검증 기록

2026-09-08 기준. 현재 검증 대상은 **여러 본문을 검색한 뒤 근거를 선택하고, 질문별로 선택한 본문만 읽어 설명하는 RAG**다. 이전 고정 본문 발췌 방식과 구분한다.

> 자동 테스트 205개 통과. 마지막 실제 실행은 세 충돌을 모두 처리했지만 **8개 답변 중 7개를 생성하고 1개는 출력 토큰 상한으로 보류한 부분 결과**다. 전체 성공이나 금융 정확성 검증 완료로 표시하지 않는다.

## 어떤 입력을 검증하나요?

`data/fixtures/tradeflow_example/`의 가상 Booking·상업송장·B/L과 금융일정 엑셀을 사용한다. 이미지 송장에는 텍스트 레이어가 없어 실제 RapidOCR를 거친다. 회사와 거래값은 합성이며 실제 운송·결제 문서가 아님을 표시했다.

| 항목 | 합성 예시의 기대 결과 |
| --- | --- |
| 거래 연결 | INV-DEMO-001 / BL-DEMO-001 / BK-DEMO-001을 엑셀 거래정보와 연결 |
| 예상 입금일 | 실제 선적 9월 21일 + 30일 = 10월 21일 |
| 대출 만기 | 10월 15일, 예상 입금보다 6일 먼저 |
| 선물환 매도 결제 | 10월 16일, 예상 입금보다 5일 먼저 |
| 공급자 지급 | 10월 19일, 예상 입금보다 2일 먼저 |
| 다른 거래의 일정 | OTHER-LOAN은 분석 제외 |

Booking 예정 출항일 9월 18일과 B/L 발행일 9월 22일은 이 거래의 입금 계산 기준이 아니다. 수출채권 보유·거래 연결·선물환 매도 방향은 합성 입력의 확인 가정이며, 은행이나 채권원장을 조회해 입증한 상태가 아니다. 다른 입금이나 보유 잔액을 계산하지 않으므로 일정 차이만으로 실제 현금 부족을 판정하지 않는다.

## 현재 검증 대상 구조

활성 공식 자료는 신한은행 기업대출 설명서, HSBC 수출채권할인 기본 계약, 중국은행 선물환 고객매도 설명서의 **3개 PDF**다. 원본 총 41페이지 중 중복·서명란 등을 제외한 **24페이지**를 색인한다. 현재 manifest v7 기준 고유 본문 **193개**, 충돌 코드별 레코드 **274개**다. 레코드 수는 상품 수가 아니다.

페이지 안의 제목·조항·목록과 임베딩 토큰 한도를 고려해 여러 청크를 만들고, 로컬 다국어 E5 임베딩으로 ChromaDB에 저장한다. 세 충돌에 총 **11개 자연어 검색 질문**을 사용하며 질문별 상위 3개 후보를 찾는다. 거래 구분과 자료군은 제한하지만 정답 페이지나 정답 주제 ID로 필터링하지 않는다. 수출채권 관련 4개 질문은 수출 거래이고 보유 확인 입력이 있을 때만 추가한다.

```text
문서·엑셀 연결 → 입금일과 금융일정 비교 → 충돌별 여러 본문 검색
  → 핵심 질문에 맞는 근거 ID 선택
  → 질문 하나 + 선택한 본문 하나로 설명 생성
  → 서버가 출처·페이지·원문을 연결 → 검토용 PDF 보고서
```

이 합성 거래에는 대출 3개, 선물환 2개, 공급자 지급 3개의 **핵심 답변 항목 8개**가 있다. 검색 질문 수와 보고서 답변 수는 목적이 다르며, 짧은 보고서에 검색한 모든 비용·조건을 출력하지는 않는다.

`choose_financial_evidence`는 질문별로 실제 검색된 후보의 ID 또는 `null`만 고른다. 이후 `explain_financial_evidence`에는 질문과 선택된 본문 하나만 전달하며 다른 후보나 이전 초안은 주지 않는다. 설명은 항목별 한 문장, 220자 이내이고 본문으로 답할 수 없으면 보류한다. 은행·파일명·페이지·인용 원문은 서버가 선택된 ID에서 연결한다.

현재 실행 설정은 `gpt-5-nano` / `flex`, 금융 근거 선택과 설명의 추론 수준은 `high`다. 전체 예시의 유료 호출 상한은 **20회**, 호출당 출력 상한은 **6,000토큰**이다. 출력 상한에는 추론에 쓰이는 토큰도 포함되며 전체 실행의 실제 사용량과 다르다. 자동 재시도나 다른 모델·요금 등급으로의 자동 전환은 하지 않는다.

| 검증 층위 | 현재 확인 내용 | 이것만으로 보장하지 않는 것 |

| 실제 LLM 전체 실행 | `20260908T063323972443Z`: 20회 시도·19회 완료, 답변 7개·보류 1개 | 모든 핵심 질문 해결, 다른 고객·계약에 대한 품질 |
| 별도 개발 대조 검토 | 5개 직접 정합, 1개 관련성 한계, 1개 범위 표현 주의 | 사람 또는 금융 전문가의 검증, 통계적 정확도 |

자동 테스트에는 외부 PyMuPDF 라이브러리의 deprecation 경고 5개가 남았다. 일반 테스트의 모의 LLM과 실제 API 실행은 구분한다. 확정된 실행 수치는 [실행 요약](verification-summary.json)에 기록했다.

완료 호출에서 기록한 사용량은 입력 27,669토큰·출력 29,158토큰이다. 실패 호출의 사용량은 포함하지 않아 청구액이나 총 사용량으로 해석하지 않는다. 13개 구조 확인 중 12개가 통과했으며, `all_key_questions_answered`는 실패했다. 실패한 수출채권 서류 답변을 모의 응답이나 이전 실행의 답변으로 채우지 않았다.

최종 7개 답변 중 연장 조건·갱신 서류·선물환 만기·중도해지·운전자금 용도는 원문과 질문에 직접 부합했다. 대출 미상환 답변은 기한의 이익 상실을 전제로 한 불이익을 설명해 근거는 있지만 원금 미상환 자체에 대한 직접성이 약하다. 환매 답변은 미지급 상황의 유예기간 말일·은행 요청·즉시 환매를 설명했지만, ‘경우에 한해’라는 표현을 전체 계약의 유일한 환매 사유로 읽으면 안 된다. 원문에는 다른 발생 사유도 있다.

보고서는 최종 실행의 답변을 바꾸지 않고 거래별 자료 연결 수와 페이지 배치만 정리하여 5페이지로 다시 렌더링했다. 최종 5페이지 모두 이미지로 확인했고, 마지막 배치 수정 후 보고서 관련 테스트 3개도 다시 통과했다. 최신 보고서에도 생성 실패와 확인 필요 경고를 유지한다.

자동 확인은 문서 3종, 예상 입금일, 세 충돌의 날짜 차이, 서비스 카드, 출처·인용 원문, 질문별 복수 검색 후보, 답변 항목, OCR, 보고서 생성 등을 점검한다. **답변이 모두 채워졌거나 원문 문자열이 일치해도 설명의 금융적 의미가 맞는 것은 아니다.** 선택한 본문이 조건·시점·주체·예외까지 직접 뒷받침하는지, 질문에 실제로 답하는지 따로 읽는다.

마지막 기록의 보류는 근거 없는 설명을 채우지 않았다는 점에서는 안전하지만, 적절한 후보를 선택하지 못했다는 한계가 남는다. 일부 보류나 구조 검사 통과를 모든 핵심 질문의 해결로 표현하지 않는다.

이를 반영해 환매 질문을 ‘언제, 누구의 요청으로’에 답하도록 명확히 했다. 생성 설명에 ‘아래·다음·위 각호’처럼 실제 조건이 없는 목록 지시어가 남으면 해당 답변만 보류한다. 이는 읽기 위한 제한적인 검사이며 금융 의미 오류 전체를 자동으로 탐지하는 장치가 아니다.

### 이전 고정 본문 버전과의 구분

과거 `20260908T003526503773Z` 실행과 자동 테스트 151개 통과 기록은 이전 고정 본문·원문 발췌 중심 버전의 결과다. 현재의 페이지 전체 청크 검색·설명 생성 구조를 검증한 수치가 아니다. `docs/TradeFlow-MVP-Guide.pdf`도 이전 버전 문서이며 현재 설명은 [RAG 설계](rag-corpus-guide.md)를 기준으로 확인한다.

## 재현

```bash
uv sync --extra dev --extra ocr
uv run python scripts/fetch_product_pdfs.py
uv run python scripts/build_product_vector_index.py
uv run python -m pytest -q
TRADEFLOW_LOCAL_MODELS=1 HF_HUB_OFFLINE=1 uv run python -m pytest -q
uv run ruff check app scripts tests
uv run mypy app

# API를 호출하지 않는 입력·색인 사전 확인
uv run python scripts/run_example.py

# .env에 새 키를 설정한 후 실제 유료 실행
uv run python scripts/run_example.py --live

# 기존 실제 실행을 질문·검색 후보·답변 Markdown으로 정리; 추가 API 호출 없음
uv run python scripts/verify_rag.py --from-result output/example/live-result.json
```

로컬 모델 테스트는 필요한 모델과 색인을 준비하고 명시적으로 활성화해야 한다. 공개 저장소를 복제한 환경에는 공식 PDF·로컬 모델·Chroma 색인을 별도로 준비한다. 실행 중인 API가 있다면 오프라인 재색인 뒤 서버를 재시작해 새 활성 컬렉션을 읽는다.

최신 전체 결과는 `output/example/live-result.json`, 실행별 결과와 호출 기록은 `output/example/live-runs/`에 저장한다. RAG 단독 기록은 `output/rag-verification/`에 있다. 보고서 경로는 실행에 따라 교체될 수 있어 과거 JSON이 과거 PDF까지 보존한다는 뜻은 아니다.

## 공개 범위와 남은 한계

API 키·비공개 추론은 실행 기록에 저장하지 않는다. 그러나 원시 실행 JSON·Markdown·PDF에는 은행 본문과 발췌가 포함될 수 있으므로 **공식 PDF, ChromaDB, 모델, 은행 본문을 포함한 결과·호출 로그·보고서는 로컬 전용**이다. 공개 대상은 코드·합성 입력·공식 링크·직접 작성한 설명과 원문을 제거한 실행 요약이다. 자료별 이용 조건은 [자료 이용 주의사항](rag-corpus-guide.md)을 따른다.

현재 검증은 한 합성 거래와 제한된 공식 자료에 대한 확인이다. 개발 대조 검토는 실행 모델과 별도로 AI 개발 도구가 결과와 본문을 비교한 작업이며, 실제 사람이나 금융 전문가가 검증했다는 뜻이 아니다. 고객별 승인·대출 가능성·계약 변경을 결정하지 않으며 금융약관 전문 해석을 자동화하지 않는다. 실무 적용에는 금융 전문가 검토, 다양한 거래·실패 사례 평가, 개인정보·보안·자료 이용 조건의 확인이 필요하다.
